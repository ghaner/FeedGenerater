二、这个源抓的是什么

该站「解析接口」列表是按最新排序的接口清单，每条给出：名称、是否收费、解析地址（带 ?url= 参数）、支持的解析格式。页面共 147 条 / 10 页，本源跟踪第 1 页（最新 15 条，过滤后 11 条）。

三、过滤「失效」是怎么做的

生成器新增可选能力 exclude：命中所配字段值的条目直接丢弃。没有配置该字段的源完全不受影响，所以这次改动不会波及 seedog / yszzq。

// src/sources.json —— yszzq_jiexi 片段
"exclude": {"field": "status", "values": ["失效"]},
"fields": {
  "title":  {"pattern": "<h2>(?:<span[^>]*>.*?</span>)?\\s*(.*?)</h2>", "strip_tags": true},
  "status": {"pattern": "<h2><span[^>]*>(.*?)</span>", "strip_tags": true},
  "api":    {"pattern": "<p>.*?</p>\\s*<p>(.*?)</p>", "strip_tags": true},
  "fmt":    {"pattern": "<p>.*?</p>\\s*<p>.*?</p>\\s*<p>(.*?)</p>", "strip_tags": true}
}

实现位置：src/generate_feed.py 的 filter_excluded(items, cfg)，在解析之后、截断之前执行；运行时会打印「已按 exclude 规则剔除 N 条」。

以后想改规则，只动配置，不动代码

  • 不再过滤失效：删掉该源里的 "exclude" 那一行，重新生成即可恢复 15 条。

  • 再加一个网址：在 src/sources.json 的 sources 数组里照抄一条，改 name / url / item_block / fields，跑 python src/generate_feed.py。
  • 本机一键：双击 seedog_rss.bat 生成并打开全部 xml；publish.bat 生成并推送。

六、避坑记录

站点会静默限速。同一 IP 短时间内连续抓取，urllib 前 1~2 次成功，之后报 read operation timed out / SSL handshake timed out / WinError 10053，而此时用 curl 访问仍是 200。这不是代码问题，冷却 60 秒后重跑即恢复，不要改代码。

生成器的设计是「某源失败就跳过、保留上一次的 feed」，所以偶发超时不会让订阅内容变空。

另外：本仓库提交前需先配仓库级 git 身份；提交应只含本次相关文件，不要把 CI 重生成的无关 xml 混进业务提交。
