一、结论先说

kkys14 没有任何影片 JSON 接口，它是「服务端渲染 + cdndefend 反爬挑战」，不是 SPA。 原先记录里"SPA 渲染未调通"的判断不成立。

但探测中发现一个更省事的通道：挑战通过后发放的 cdndefend_js_cookie 是静态值， 带上它用普通 urllib 直连就返回 200 和完整 HTML，1.06 秒拿到 24 条，完全不需要 Playwright。

原先提取 0 条的真实原因也查清了：页面在加载约 3.9 秒后被反调试脚本自动跳转到 www.baidu.com， 而旧逻辑取 DOM 的时机正好在跳转之后，拿到的自然是百度页面。

五、需要你手动操作的清单

  1. 在 GitHub 仓库配置 Secret（首次必须）。Settings → Secrets and variables → Actions → New repository secret，名称填 KKYS14_COOKIE，值填 cdndefend_js_cookie=75CB7DA5DBA9A7ED39E1EF38401E19B8BBFFD58A14423（完整一行）。
  2. 推送代码。本会话已本地提交 f1a5a34，但 push 三次均失败（代理返回 CONNECT tunnel failed 502， 与项目既有记录一致，属环境网络问题）。请在本机执行：git push origin main，或双击 publish.bat。
  3. 云端首跑验证。推送后在 GitHub Actions 页面手动 Run workflow，检查日志中 kkys14 是否 提取到 24 条。若出现 HTTP Error 850 且刷新也失败，说明 CI 机器 IP 被拦，需回来告知我调整。
  4. 订阅地址。Pages 重建约 40~90 秒后生效： https://ghaner.github.io/WebFeedGitHubGenerater/kkys14.xml
  5. 日后 cookie 失效怎么办。浏览器打开目标页 → F12 → Application → Cookies → 找到 cdndefend_js_cookie 并复制其值，拼成 cdndefend_js_cookie=<值>， 更新到 GitHub Secret KKYS14_COOKIE 与本机 src/local_secrets.json。
