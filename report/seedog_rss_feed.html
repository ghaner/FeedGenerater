五·排错：加载源码是 Cloudflare 挑战页（Just a moment…）

现象：你截图里「页面源代码」全是 challenges.cloudflare.com / Just a moment...，且「代理」复选框是勾选状态——这正是失败原因。

核心结论：请先「取消勾选代理」。 rsseverything 的代理走数据中心 IP，被 Cloudflare 按 IP 信誉直接判为机器人——无论填什么 UA 都回挑战页。我们脚本实测：关掉代理、用服务器直连 + 完整 Chrome UA + 跟随 302，能稳定拿到 200 + 20 条真实影片（covers=20，挑战页=0）。代理 IP 信誉比直连更差，所以勾代理必败，关代理才有机会过。

✅ 步骤二（若步骤一仍显示挑战页：rsseverything 服务器 IP 也被标记）

Cloudflare 的 Managed Challenge 按「IP 信誉 + JS 质询」双重判定。若步骤一仍失败，说明 rsseverything 自己的服务器 IP 也在黑名单里，需要带一个真实浏览器刚拿到的 cf_clearance Cookie：

  1. 用真实 Chrome / Edge 打开 https://seedog.cc/?order=update，等它自动通过验证（看到影片列表）。
  2. 按 F12 → Application（应用）→ Cookies → https://seedog.cc。
  3. 在 Cookie 列表中找 Name 列 = cf_clearance 的那一行（⚠️ 不是 XLA_CI、不是 __cf_bm、也不是别的；XLA_CI 只是普通站点 Cookie，不能绕过 Cloudflare）。点开它，复制它的 Value（一串很长的十六进制）。
  4. 「代理」保持不勾；Custom curl parameters 改为（把值换成你刚复制的 cf_clearance 值）：
    -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36" -b "cf_clearance=此处粘贴你复制的值"
  5. 重新加载 → 带有效 clearance cookie 即可绕过质询，出现 20 条。

❗ 常见错误：把 XLA_CI 的值当成了 cf_clearance 填进去（图2 里默认选中并展示的就是 XLA_CI）。rsseverything 里写 cf_clearance=旧值 等于「用错钥匙还贴了 cf_clearance 的标签」，Cloudflare 校验失败，仍弹挑战页。必须复制 Name 真的叫 cf_clearance 的那条。

已复制 ✓

⚠️ cf_clearance 有效期约 30 分钟～数小时，过期需重取；它绑定「域名 + 浏览器指纹 + IP」，换设备可能失效。

💡 实测对照（同机脚本复现）：直连 + 完整 Chrome UA + 跟随 302 → 200, covers=20, 挑战页=0；而经 rsseverything 代理（数据中心 IP）→ 挑战页。说明卡点在 IP 信誉，而非提取规则。规则已验证无误，只要源码能正常加载即可提取。另：sidhub.cc 与 seedog.cc 内容字节级一致（同 38774 字节、20 条），规则通用。
